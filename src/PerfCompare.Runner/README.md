# PerfCompare.Runner

Консольна програма запускає застосунок за сценарієм задану кількість разів, міряє час виконання, піковий обсяг пам'яті й процесорний час кожного запуску та відправляє результат на сервер або зберігає його у файл. Загальна архітектура описана в [docs/architecture.md](../../docs/architecture.md).

## Команди

```bash
PerfCompare.Runner run <scenario.yaml> [--server <url>] [--out <файл>] [--results-dir <папка>]
PerfCompare.Runner send <файл|папка> --server <url>
```

З вихідного коду: `dotnet run --project src/PerfCompare.Runner -- run scenarios/baseline.yaml --server http://localhost:5000`.

| Параметр | Призначення |
|---|---|
| `--server <url>` | відправити результат на сервер (3 спроби з паузою 2 секунди) |
| `--out <файл>` | додатково зберегти результат у JSON-файл |
| `--results-dir <папка>` | куди зберегти результат, якщо сервер недоступний (за замовчуванням `results`) |

Без `--server` і `--out` результат виводиться в консоль як JSON.

## Сценарій

```yaml
name: baseline
command: samples/bin/CpuBound
args: ["2000000"]
repeats: 5
timeoutSeconds: 30
warmup: 1
workingDirectory: .
```

Правила полів: `name` до 100 символів, `command` не порожній, `repeats` від 1 до 100, `timeoutSeconds` від 1 до 3600, `warmup` не менше 0. Невідомі ключі відхиляються. Порожній `args:` означає відсутність аргументів. Шлях у `command`, що містить `/`, рахується від поточної папки; на Windows розширення `.exe` додається автоматично.

## Як працює серія

1. Спочатку виконуються прогрівні запуски (`warmup`), їх результати відкидаються.
2. Кожен вимірюваний запуск виконується окремим процесом із таймаутом. Програма, що не вклалась у `timeoutSeconds`, зупиняється разом з усім деревом процесів і отримує статус `Timeout`.
3. Для кожного запуску записуються `durationMs`, `peakMemMb`, `cpuTimeMs`, `exitCode` і `status` (`Passed`, `Failed`, `Timeout`). Не вдалий старт програми дає `Failed`, серія триває.
4. `Ctrl+C` завершує поточну ітерацію й зупиняє серію, уже зібрані вимірювання відправляються як часткова серія. Другий `Ctrl+C` завершує програму негайно.
5. Результат разом з відбитком середовища (ОС, версія, середовище виконання, ядра, пам'ять) відправляється на сервер. Якщо сервер недоступний, результат зберігається у файл, а відправити його пізніше можна командою `send`.

## Коди виходу

| Код | Значення |
|---|---|
| 0 | серію виконано, результат збережено або відправлено |
| 1 | результат не вдалося відправити (його збережено у файл) |
| 2 | неправильна команда або некоректний сценарій |
| 3 | помилка виконання: наприклад, неможливо записати файл результату |
| 130 | серію перервано користувачем |

## Тести і покриття

```bash
dotnet test tests/PerfCompare.Runner.Tests
./scripts/coverage.ps1 -Name Runner
```

Другий рядок будує звіт `docs/reports/coverage-runner.md` і завершується помилкою, якщо покриття рядків нижче 80%. Крайні випадки описані в [docs/edge-cases-runner.md](../../docs/edge-cases-runner.md).
